# 审计分类与交付规则

## 审计状态

- `supported`（证据充分）：所提供证据支持全部关键事实和限定条件。
- `partial`（部分支持）：存在相关证据，但遗漏或缩小了某项关键事实。
- `unsupported`（缺少证据）：证据包中没有足够相关的支持内容；这并不等于结论一定错误。
- `conflict`（证据冲突）：数值、单位、主体、日期、品类、口径、肯定/否定表述或其他来源直接不一致。
- `stale`（证据过期）：报告中的“当前有效”等表述依赖已过期或超出时效窗口的证据。
- `needs_review`（需要复核）：OCR 或来源定位不确定，无法形成可靠的自动结论。

## 问题代码

- `missing_evidence`：缺少证据；`weak_support`：支持不足。
- `numeric_mismatch`：数值不一致；`unit_mismatch`：单位不一致；`date_mismatch`：日期不一致。
- `entity_mismatch`：主体不一致；`scope_mismatch`：统计口径不一致；`qualifier_overreach`：表述过度。
- `source_conflict`：来源冲突；`stale_evidence`：证据过期；`ocr_uncertainty`：OCR 不确定。
- `derived_calculation`：衍生计算核对；`locator_uncertainty`：来源定位不确定。

问题代码说明发现产生的原因；审计状态说明报告结论与证据之间的总体关系。

## 人工决定

- `accept`（确认发现）：确认风险发现成立，仅表示知悉，不能解除高风险阻断。
- `reject`（驳回误报）：确认该发现属于误报。必须填写理由，建议选择支持该判断的证据编号。
- `replace`（修正并复验）：只替换已定位的报告文字。修正内容必须用现有证据重新核对，并达到 `supported` 才能解除阻断。
- `waive`（正式豁免）：不修改报告结论，书面接受业务风险。必须填写理由和风险责任人；未填写到期日表示永久豁免，临时豁免使用 `YYYY-MM-DD`，到期后不再解除阻断。

每次决定都作为新事件追加，不得删除早期记录。最新事件决定当前处理状态，完整历史始终保留在审计轨迹中。

## 满足交付的条件

仅在以下条件全部成立时设置 `delivery_ready=true`：

1. 审计任务完成并生成了风险发现；
2. 全部证据文件均成功解析；
3. 审计后输入快照和原文件均未变化；
4. 每个高风险发现都通过有理由的误报驳回、复验通过的修正或正式豁免完成闭环；
5. 最终导出同时重新生成报告、台账、审计 JSON 和产物清单。

不得仅凭 `accept` 解锁交付。
