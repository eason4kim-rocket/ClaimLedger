# ClaimLedger 总决赛现场评委 6 大尖锐 Q&A 问答预案与满分防御策略

在 Intel Connection 大会总决赛路演中，评委团队由**英特尔芯片架构师/系统工程师、魔搭社区技术负责人、企业投资人与大型政企 CIO** 组成。他们会从底层算力、业务商业化、大模型自反思能力等不同刁钻角度发难。

以下提炼出 6 大高频“杀手级”质询与标准防御话术：

---

### Q1（基础软件与大模型架构师）：
**“为什么一定要专门搞一个规则引擎加本地小模型做审计？现在的头部大模型（如 Qwen-Max、DeepSeek-V3、Claude 3.5 Sonnet）直接做一次‘自反思（Self-Reflect）’或者‘联网 RAG’，让大模型自己审自己，难道不更简单吗？”**

#### 💡 满分防守策略（直击本质，彻底打碎“大模型自审”的幻象）：
> **“评委老师，这正是大模型在企业严肃交付中最大的认知误区——‘用概率去审核概率，只能得到更大的概率幻觉’。”**
>
> 1. **无法自证（Self-Bias 悖论）**：认知心理学与大模型评测都证明，大模型具有极强的自确认偏误（Self-Confirmation Bias）。生成虚假数字的模型，在自审时往往倾向于编造新的论据来掩盖旧的错误；
> 2. **事实不可计算性**：大模型本质是基于注意力机制的 Next-Token 概率预测器。在面对 `02_TCO测算.xlsx` 里的复杂嵌套税费公式、跨 Sheet 运费累加时，大模型必然出现四舍五入错误或尾差失衡。**数学与财务是确定性的，必须由确定性规则和精确公式求解器把关**；
> 3. **证据坐标无法钉死**：云端大模型即便觉得‘可能有误’，也无法把原件的 PDF 物理坐标（Bbox）、Word 段落 Run、Excel 工作表单元格以确定性的数据结构（JSON/Manifest）存证；
> 4. **合规红线**：企业的底价、纪要属于商业秘密，绝不可能发送到云端大模型做“二次自审”。**用端侧确定性规则为大模型建立物理防波堤，才是工业级落地的唯一解法。**

### Q2（英特尔硬件与系统专家）：
**“你们在 Intel Core Ultra 上跑 OpenVINO，模型如果吃满内存或者轻薄本发烫降频怎么办？既然 Lite 模式纯靠确定性规则和 OCR 已经表现很好了，为什么还要引入本地 8B 生成模型？”**

#### 💡 满分防守策略（展现扎实的工程素养与阶段性显存释放设计）：
> **“非常感谢老师极其专业的硬件工程质询！我们在架构设计时就将‘资源防御性’列为第一红线。”**
>
> 1. **科学分级（Profile 分流）**：我们在系统中设计了明确的阶梯式运行模式：
>    * 日常高频审计默认采用 **`lite` 模式**（仅占用百兆级内存，轻薄本全天运行零负担，风扇不转）；
>    * 只有在用户提出复杂长文本因果推理、非结构化复合语义重排时，才显式 Opt-in 启用 **`balanced` 模式**；
> 2. **阶段性显存释放（Phase-based Memory Lifecycle）**：
>    * 我们在 `src/claimledger/semantic.py` 中实现了严格的阶段式加载调度：**Qwen3-8B 关键结论抽取完成后，立即显式销毁上下文并释放显存**，然后才轻量加载 Embedding 与 Reranker；任务结束，临时 Localhost 独立网关进程直接按 PID 强杀彻底退场；
> 3. **精准调度到 xPU**：
>    * 配合 OpenVINO，我们让高频常驻任务锚定在 NPU（单位数瓦特功耗），脉冲式吞吐交给 iGPU，精细逻辑交给 CPU，避免 CPU 单核持续 100% 满载导致的降频发烫。

### Q3（大型政企 CIO / 采购总监背景评委）：
**“在真实的采购或重大决策中，很多结论其实就是‘领导拍板’或‘综合定性判断’，证据根本没有形成闭环，或者各方意见本来就是冲突的。你的系统直接把交付闸门锁死（Delivery Gate Locked），会不会卡死业务，导致根本交不了差？”**

#### 💡 满分防守策略（体现“以人为本”与 Human-in-the-loop 的管理智慧）：
> **“评委老师点出了政企公文流转中最精妙的管理实际！ClaimLedger 的设计原则不是‘机器代替人拍板’，而是‘让机器把暗礁照亮，把裁决权交还给负责人’。”**
>
> 1. **审计不等于批准**：系统卡死交付门禁，防的是‘经办人和领导在完全不知情的情况下被 AI 蒙蔽、闭眼签字’；
> 2. **四维决策支持（Accept / Reject / Replace / Waive）**：
>    * 如果是数字搞错了，点击 `replace` 一键纠偏并复验；
>    * 如果纪要确有特殊背景、领导决定特批，负责人可以使用 `waive`（正式豁免）！
> 3. **法定豁免留痕（Accountability）**：
>    * 一旦选择 `waive`，系统强制要求填写真实审批人姓名和书面豁免理由。门禁随即绿灯放行，但这笔豁免会被白纸黑字永久写入导出的 `claim_ledger.xlsx` 决定日志与数字哈希中。
>    * **这就做到了：既不耽误业务紧急流转，又在制度上杜绝了事后‘扯皮甩锅、责任不清’的灰色地带。**

### Q4（魔搭社区 / Agent 平台评委）：
**“现在市面上有许多基于 LangChain、LlamaIndex 做的多 Agent 框架，也有很多基于 MCP 协议的工具。ClaimLedger 作为一个 Agent Skill，与它们是什么关系？如何证明你们的‘乐高式集成’不是一句空话？”**

#### 💡 满分防守策略（突出标准规范遵循与双向互操作性）：
> **“我们完全遵循 Anthropic 与 ModelScope 官方定义的 Agent Skills 规范标准，在设计上实现了‘标准解耦与双向调用’。”**
>
> 1. **三级渐进式加载（Progressive Disclosure）**：
>    * 很多所谓的 Agent 工具把几十页规则塞进 System Prompt，导致宿主 Agent 瞬间发生‘上下文幻觉与膨胀’；
>    * ClaimLedger 仅将 30 个 Token 的 YAML 元数据暴露给宿主，Agent 仅在意图高度匹配时才按需读取 `SKILL.md` 与参考文档，保证零上下文污染；
> 2. **双向互操作实测**：
>    * **作为 Gatekeeper 被调用**：在 QwenWork、Trae 或企业自研的协同平台上，写作 Agent 输出 DOCX 之后，能以标准 Tool Call 语法自动唤起 ClaimLedger 进行离线事实校验；
>    * **调用下游工具**：ClaimLedger 检出问题后，可以通过标准协议调用下游的 Office 批注工具、企业微信审批机器人或归档系统；
> 3. **自包含 GenUI**：我们提供单文件自包含的 HTML 卡片，只通过宿主平台的单向消息桥梁传递中文意图，绝不夹带任何恶意代码或网络隐蔽回传。

**“这个项目做得很扎实，但如果只是一款给个人用的端侧软件，天花板会不会太低？你们未来的商业化变现模式是什么？企业凭什么花大钱买你们？”**

#### 💡 满分防守策略（算清客户 ROI 账与软硬一体落地路径）：
> **“评委老师，这恰恰是当前大模型商业化中最能收得到真金白银的‘刚需避险场景’！”**
>
> 1. **客户付费意愿极强（买的是‘免死金牌’）**：
>    * 传统的降本增效工具，企业往往觉得‘可有可无’；但 ClaimLedger 解决的是**“防贪腐、防审计追责、防违规赔偿”**。对于千万级采购、投行 IPO 保荐或重大投资，一次失误导致的处罚就是上千万元，企业非常愿意为这种‘合规防线’支付数十万级专项预算；
> 2. **三级商业化漏斗**：
>    * **开源基座版**：吸引广泛开发者和专业审计从业者，建立行业信任与标准规则生态；

### Q6（评测与准确率挑剔型专家）：
**“你们汇报的指标是 Recall 97.96%、Precision 100%，这在工业界几乎是不可思议的完美数据。你们怎么保证这不是‘过拟合（Overfitting）’？面对全新未见过的杂乱业务文档，你们的表现会断崖式下跌吗？”**

#### 💡 满分防守策略（诚实拆解数据本质，彰显科学家与工程师素养）：
> **“非常感谢老师一针见血的质询！我们首先要诚实说明：这个成绩来自包含 100 条结论、49 处复杂业务风险的三行业‘合成黄金基准集（golden-v2）’，我们绝不在评委面前夸大其为‘全场景无条件 100%’。”**
>
> 1. **为什么查准率能达到 100%？**：
>    * 因为我们的核心设计哲学是**“确定性规则与物理坐标锚定”**。我们不是让大模型去猜，而是从原件中提取数字、税率、时间戳做严格逻辑比对；只要抓出矛盾，必有底层 Excel 单元格或扫描件物理坐标为证，因此没有虚假警报；
> 2. **面对未知生僻场景的泛化机制**：
>    * 我们将“核心引擎”与“行业规则包（YAML）”做了彻底解耦。针对不同行业，用户只需配置简单的键值对规则（如采购关注含税/运费，运营关注履约率分母）；
>    * 即便在没有任何行业规则的完全生僻领域，系统会自动降级为 **`generic-zh` 通用模式**，依然能完成 100% 精度的纯数值差异、日期跨期、绝对化夸大词的确定性过滤；
> 3. **开放共建生态**：
>    * 我们开源了规则包格式和构建工具，欢迎全行业专家持续提交各垂直领域的审计规则，让系统像防病毒软件的病毒库一样，持续自我进化！
