# ClaimLedger 评测报告

> 本页只记录实际运行结果。未完成的客户验证、人工耗时和 Intel AI PC 测试明确标为待测，不用推测值占位。

## 1. 评测范围与披露

主评测集 `claimledger-procurement-flagship-v1` 是公开问题原型驱动、脱敏重构并主动植入错误的采购续约案例，不是客户材料或客户背书。它用于验证解析、OCR、结论提取、证据回跳、规则判断与交付闭环能否在一个可复现案例中协同工作。

在同一重构黄金集上取得高分，只能证明当前版本没有破坏这个封闭案例，不能直接外推到未见行业、真实客户材料或任意 OCR 质量。

跨行业集 `claimledger-cross-industry-golden-v2` 增加运营月报和咨询市场进入报告。本文同时披露两个数据集的当前结果，不用单案例成绩冒充跨行业成绩。

## 3. 数据集构成

| 项目 | 采购主案例 | 跨行业黄金集 |
|---|---:|---:|
| 可核查结论 | 44 | 100 |
| 预期风险结论 | 23 | 49 |
| 预期支持结论 | 21 | 51 |
| 证据组 | 17 | 36 |
| 实际证据文件 | 19 | 38 |
| 解析后的可定位证据片段 | 173 | 369 |

23 条风险标签的主状态分布为：`conflict` 15 条、`partial` 3 条、`unsupported` 2 条、`stale` 2 条、`needs_review` 1 条。部分标签允许相邻状态作为可接受答案，避免把合理的 `partial`/`conflict` 边界差异误算成失败。

案例覆盖：

- 价格、税费、运费与到岸成本；
- 供应商份额和委员会授权；
- 准时交付率、缺陷率和交付周期；
- 报告、证书有效期与主体名称；
- 检测能力范围与低清扫描件；
- 产能声明、现场核验和来源冲突；
- 三张银行回单的累计金额与收款主体；
- 无条件续签等结论越权。

跨行业集由采购 44 条、运营 28 条和咨询 28 条结论组成，49 条风险分别为 23、12 和 14 条。三个证据目录均解析为 `complete`，共 369 个证据片段，超过原定 250 条证据片段门槛。

## 4. 当前结果

### 4.1 采购主案例

| 指标 | 结果 | 分子 / 分母 |
|---|---:|---:|
| 结论提取 Precision | 100% | 44 / 44 |
| 结论提取 Recall | 100% | 44 / 44 |
| 结论提取 F1 | 100% | — |
| 风险识别 Precision | 100% | 22 / 22 |
| 风险识别 Recall | 95.65% | 22 / 23 |
| 风险识别 F1 | 97.78% | — |
| 状态准确率 | 93.18% | 41 / 44 |
| 证据来源文件 Top-5 召回率 | 90.91% | 40 / 44 |
| 证据解析覆盖 | `complete` | 19 / 19 文件 |

本次阶段耗时：

| 阶段 | 耗时 |
|---|---:|
| 证据解析与 OCR | 64,518 ms |
| 召回与核验 | 3,379 ms |
| 总计 | 67,998 ms |

结果 JSON 同时输出了 `high_risk_recall=0` 和若干 `issue_code_* = 0`。这不是“测得 0 分”，而是该版本标签集尚未提供高风险级别与 issue-code 金标，分母为 0；因此这些指标属于“未测”，不得拿来宣传或与其他方案比较。

采购集达到结论提取和风险识别门槛。唯一风险漏检是“检测报告样品与采购品一致”的规格范围问题；Top-5 仍有 4 条预期来源文件未进入前五。这些是真实的发布前优化项，不应隐藏。

这里的 90.91% 只检查候选证据的文件名，因为早期 standalone 标签没有保存 `evidence_quote` 和 `evidence_locator`。跨行业集对每条结论同时检查文件名、精确原文和精确定位，因此下方 91% 是更严格、也更适合作为发布基准的证据指标。两个数据集使用独立重生成的 DOCX/证据文件和全新任务目录，不是同一 job 缓存造成的差异。

| 指标 | 当前结果 |
|---|---:|
| 结论提取 Precision / Recall / F1 | 100% / 100% / 100% |
| 风险识别 Precision / Recall / F1 | 100% / 97.96% / 98.97% |
| 状态准确率 | 97.00% |
| 文件 + 精确原文 + 精确定位 Top-5 召回率 | 91.00% |

分场景结果说明当前泛化差距：

| 场景 | 风险 Precision | 风险 Recall | 风险 F1 | 状态准确率 | Top-5 |
|---|---:|---:|---:|---:|---:|
| 采购（跨行业重生成版） | 100% | 95.65% | 97.78% | 93.18% | 79.55% |
| 运营月报 | 100% | 100% | 100% | 100% | 100% |
| 咨询市场报告 | 100% | 100% | 100% | 100% | 100% |

跨行业评测已经稳定识别 48/49 条风险且无误报，严格 Top-5 也达到 91%；主要短板转为采购异构证据的精确排序、高风险严重度映射和 issue-code 完整性。它证明数据集不仅能产生总分，也能定位下一轮工程优化。

2026-07-19 的 v0.4.1 最终统一 `lite` fresh-task 运行中，采购、运营和咨询三案总耗时分别为 52,135 ms、1,402 ms 和 1,450 ms。采购包含扫描 PDF、TIFF、JPG 和三张回单，OCR 是主要耗时；运营和咨询证据具备可直接解析的文本层，因此同一 Lite profile 不会为了“用了 OCR”而重复识别文本材料。本批次进程峰值 RSS 为 3,062,497,280 bytes；这是含 PaddleOCR 运行时和三案串行任务的进程峰值，不等同于单页 OCR 的增量内存。

机器可读结果保存在 `docs/results/golden-v041.json`。三案标准产物均已生成；由于金标不是人工交付决定，评测器不会自动替用户执行 `reject`、`replace` 或 `waive`，所以 `delivery_report.docx` 仍由真实人工闭环门禁控制。

## 5. 自动化测试

当前回归集覆盖：

- 相邻数量与容量单位、日期标准化、金额与百分比；
- 实体份额反转、跨来源冲突和累计回单计算；
- DOCX 跨 run 结论、表格定位、原生批注与格式保留；
- XLSX 工作表/单元格定位和公式注入防护；
- PDF 文本层优先、扫描页 OCR、低置信度与缓存；
- 证据 Top-5 文件多样性；
- append-only 决定日志、替换复核、交付门禁和输入哈希变化；
- 本地个人配置、岗位模板、先例快照、策略草稿/激活/停用和配置隔离；
- 豁免先例不可提升、拒绝先例的高相似度门槛和历史任务不可变；
- 盲标 Excel 导出/导入、一致率、Precision/Recall/F1 与分歧清单；
- OpenVINO localhost 模型网关的独立令牌、端点契约和模型角色白名单；
- localhost API 令牌、任务归属、路径与证据访问边界；
- Manifest 的输入、输出和规则哈希。

已运行的当前测试批次为 77 项全部通过；Paddle SWIG 与 Starlette 的上游弃用警告不影响测试结果。

## 7. 尚未完成、不得宣称

- 由第二位独立复核员盲标并确认的 issue-code 与高风险级别；
- 真实业务盲测和跨客户泛化结果；
- 人工流程与 ClaimLedger 辅助流程的计时对照；
- “审稿耗时减少 70%”等生产力结论；
- Intel AI PC 的 CPU/GPU 首次加载、峰值内存和端到端性能；
- 获奖、商业客户、采购意向或生产环境部署。

当前 100 条结论、369 个解析证据片段和 49 条植入风险已经达到数量门槛，但仍是团队构造与复核的数据集，不等于独立客户盲测。
